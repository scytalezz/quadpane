# 외부 파일 드래그 및 복구 점검 (2026-11-06)

v0.9.3 이후 작업 트리의 수정 기록입니다. 정식 버전이나 GitHub 릴리스를 변경하지 않습니다.

## 확인한 현상

실행 중인 v0.9.3 화면에서 Windows 파일 드래그 응답 연결 오류와 복구 대기 상태를 확인했습니다. 작업 결과 창에는 이동 완료 1개와 클립보드 갱신 실패 경고가 함께 남아 있었습니다. 이 기록만으로 최초 실패 원인이나 각 메시지가 같은 작업에서 발생했는지는 확정할 수 없습니다.

점검 당시 셸·이동 도우미 프로세스는 없었습니다. 복구 버튼을 누른 뒤 일반 대기 표시로 돌아오는 것은 화면에서 확인했습니다. 사용자 파일을 복사하거나 이동하는 재현 작업은 하지 않았습니다.

## 수정 원칙

- 정상적인 응답 스트림 종료와 실제 통신 오류를 구분합니다. 깨끗한 EOF 후에는 최대 100ms 동안 프로세스 종료 코드를 기다려, 드롭 승인 전 감시 종료 코드 2를 취소로 분류합니다. 종료가 확인되지 않으면 연결 오류를 보고합니다.
- 실제 파일 변경이 시작된 뒤 응답이 끊긴 경우, 시간 경과만으로 작업을 취소했다고 간주하거나 파일 작업을 자동 재시도하지 않습니다.
- 이동 도우미가 시작된 뒤 발생하는 프로세스 오류도 실제 종료까지 작업 예약을 유지합니다. 중복 이동이나 호환 경로 재실행을 막습니다.
- 복구 성공 응답을 해당 드래그·메뉴 요청에 연결합니다. 같은 요청의 오류 응답이 늦게 와도 복구 대기 상태를 다시 켜지 않으며, 다른 요청의 오류나 복구 실패는 지우지 않습니다.
- 복구가 진행 중이거나 필요한 상태에서는 드롭을 거부합니다. 이전 네이티브 드래그와 다른 경로의 외부 파일을 내부 이동으로 처리하지 않습니다. 네이티브 파일 드롭의 OLE 응답은 COPY로 고정해, 비동기 파일 처리 완료 전에 외부 앱에 원본 삭제를 허용하지 않습니다.
- 실제 파일 처리와 클립보드 후처리가 끝나면 전체 작업 예약을 해제합니다. 뒤따르는 폴더 목록 갱신은 각 패널에서 처리하며, 다른 경로로 탐색 중인 패널에 대한 드롭 차단은 유지합니다.

## 검증 범위

- 전체 Node 테스트: 409개 통과, 2개 건너뜀, 실패 없음. 별도 드라이브의 복사·이동 검사도 포함합니다.
- 셸 도우미 테스트 87개에는 실제 격리된 자식 프로세스의 EOF → 종료 코드 2 순서, 종료 없는 EOF, 실제 통신 오류, 변경이 시작된 작업의 보호 검사가 포함됩니다.
- 이전 렌더러 최적화 회귀 검사 9개 통과.
- 헤드리스 브라우저의 복사·붙여넣기·외부 드롭 경합 검사 37개 묶음 통과.
- 헤드리스 브라우저의 드래그 복구 검사 13개 묶음 통과.
- 숨김 Electron 창의 renderer/preload/main 통합 검사 8개 묶음 통과. 격리된 실제 파일로 복사·이동·이름 변경을 확인하며, 시스템 클립보드와 셸 호출은 대체 응답을 사용합니다.
- 포터블 EXE를 한글 경로의 별도 프로필에서 실행하고, 프로필과 EXE의 위치를 옮겨 다시 실행하는 검사 통과. 실제 테스트 폴더 읽기·설정 유지·정상 종료·임시 런타임 정리를 확인했습니다. 기존 작업 표시줄 고정 항목은 바뀌지 않았습니다.
- 패키지의 `app.js`, `file-operations.cjs`, `shell-menu.cjs`가 검증한 작업 트리의 바이트와 일치합니다.
- 독립 리뷰 승인: 별도 작업 공간에서 백엔드 및 화면 검사를 다시 실행하고, 수정 제거 시 회귀 검사가 실패하는 것도 확인했습니다. 재현된 차단 결함은 없었습니다.

자동화된 지연·통신 오류 재현은 실제 Windows 탐색기와의 물리적 드래그 재현을 대체하지 않습니다. 원래 사용 환경의 간헐적 실패가 모두 해결됐는지는 프리뷰로 추가 확인이 필요합니다.
