## 수정한 문제

v0.8.0에서 마우스 버튼을 놓은 뒤에도 네이티브 도우미가 마우스 입력을 계속 붙잡아, Quadpane 메뉴·드래그뿐 아니라 Windows 탐색기 드래그도 막히는 문제가 있었습니다. Windows 상태 조회에서 버튼이 모두 해제된 상태의 캡처 잔류를 확인했고, 해당 도우미만 종료한 뒤 사용자가 탐색기 드래그 복구를 확인했습니다.

- 드래그 시작 전 실제 마우스 버튼 상태를 확인합니다. 버튼 해제 입력이 누락되면 드롭 확정 전에 취소해 입력을 돌려줍니다.
- 앱과의 연결 종료를 별도로 감시해 응답하지 않는 도우미도 종료합니다.
- 메뉴·드래그 중복 요청을 차단하고 `Escape` 취소 후 입력 복구를 보강합니다.
- 요청 검증·준비와 클립보드 응답 대기에 시간 제한을 적용합니다. 실제 드롭이나 셸 명령이 실행되기 시작하면 오래 걸린다는 이유로 자동 중단하지 않습니다.

조사 내용과 수정·검증 범위는 [셸 메뉴·드래그 복구 기록](https://github.com/scytalezz/quadpane/blob/v0.8.1/docs/shell-recovery.md)을 참고하세요.

## 실행과 업그레이드

기존 Quadpane를 완전히 종료한 뒤 `quadpane-0.8.1-portable-x64.exe`를 쓰기 가능한 폴더에 두고 실행하세요. 기존 `quadpane-data/`를 새 EXE 옆에 그대로 두면 열린 폴더·작업 공간·즐겨찾기·테마·표시 설정을 이어서 사용할 수 있습니다. 설치·관리자 권한·별도 Node.js는 필요하지 않습니다.

사용법은 [포터블 안내](https://github.com/scytalezz/quadpane/blob/v0.8.1/PORTABLE.md)와 [단축키·기능 안내](https://github.com/scytalezz/quadpane/blob/v0.8.1/README.md)를 참고하세요.

## 검증 범위

로컬 문법 검사 34개 파일과 자동 테스트 201개가 통과했습니다(실패·건너뜀 없음). 도우미 멈춤·종료, 드래그 취소·경쟁 상황과 다른 드라이브 간 파일 이동을 포함합니다. 수정본의 물리적 외부 앱 드롭과 모든 셸 확장 조합은 자동 검증 범위에 포함하지 않습니다.

배포 후보 EXE의 셸 연동 7개, 표시·선택·이동 10개, 탐색 9개 검사 그룹과 포터블 런처 3회 실행도 통과했습니다. 최초 실행·재실행·EXE와 설정 폴더 이동 후 설정 복원 및 정상 종료를 확인했습니다. 셸 연동 화면 검사에서는 메뉴·드래그·클립보드 IPC를 테스트용 응답으로 대체했습니다.

Windows CI는 문법 검사·자동 테스트·포터블 빌드를 실행하고 EXE와 SHA-256 체크섬을 아티팩트로 제공합니다. v0.8.0의 테스트·프리뷰 결과는 과거 이력이며, 이번 수정본의 검증 결과를 대신하지 않습니다.
