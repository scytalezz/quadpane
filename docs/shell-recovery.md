# Windows 메뉴·드래그 멈춤 수정

2026-10-15 조사 기록. v0.8.0 배포 후 확인한 문제와 [v0.8.1 수정 내용](releases/v0.8.1.md)입니다.

## 확인한 현상

- Windows 파일 드래그와 오른쪽 클릭 메뉴가 계속 사용 중이라는 오류를 표시했습니다.
- 같은 PC의 Windows 탐색기에서도 드래그가 동작하지 않았습니다.
- 실행 파일의 SHA-256은 GitHub에 게시한 v0.8.0과 일치했습니다.
- Windows의 `GetGUIThreadInfo`로 조회한 결과, `Quadpane.Shell.exe`의 스레드가 마우스 캡처를 보유하고 있었습니다. 같은 시점에 왼쪽·오른쪽 버튼과 Escape는 모두 해제 상태였으며 클립보드 잠금 소유자는 없었습니다.
- 해당 도우미 프로세스만 종료한 뒤 사용자가 탐색기 드래그의 정상화를 확인했습니다. 탐색기 프로세스와 주 앱은 종료하지 않았습니다.

Windows 메뉴와 외부 드래그는 같은 도우미를 사용합니다. 드래그가 완료 응답을 돌려주지 않으면 새 메뉴와 드래그가 사용 중 상태로 차단됩니다. 이번 실행에서 도우미에 남은 캡처와 탐색기 장애의 관계는 확인했으나, 최초 입력이 어떤 순서로 누락되었는지는 당시 기록만으로 확정할 수 없습니다.

## 수정 내용

- **드래그 시작·종료:** 실제 기본 마우스 버튼이 눌려 있을 때만 드래그를 시작합니다. 좌우 버튼을 바꾼 설정도 반영합니다. 이미 해제된 입력을 뒤늦게 받거나 오래된 눌림 상태를 받으면 임의로 드롭하지 않고 취소합니다.
- **남은 캡처 복구:** 드롭 확정 전, 버튼 해제와 캡처가 함께 지속되면 1초 후 취소 상태로 바꾸고 2초 후에도 남아 있으면 해당 도우미만 종료합니다. 실제 대상 앱의 파일 전송 단계에 들어간 경우에는 이 감시로 중단하지 않습니다.
- **요청 중복·취소:** 응답 대기 중인 드래그를 별도로 추적해 중복 드래그와 메뉴 호출을 막습니다. `Escape`로 취소할 수 있고, 이전 요청의 늦은 응답이 새 드래그 상태를 지우지 않도록 했습니다.
- **응답 대기:** 경로 검증·셸 준비는 각 30초, 클립보드는 15초로 대기를 제한합니다. 메뉴가 열린 상태와 실제 드롭·셸 명령 실행 단계에는 절대 시간 제한을 적용하지 않습니다. 시간 초과 시 자동 재실행하지 않으며, 실행 여부가 불확실하면 파일 결과를 확인하도록 알립니다.
- **종료:** UI 스레드와 별도로 앱 연결 종료를 감시합니다. 앱 종료 시 설정·앱 내부 파일 작업 처리와 도우미 종료를 조정하고, 응답하지 않는 도우미가 남는 경우도 정리합니다. 이미 외부 앱에 넘긴 파일 작업을 되돌리는 기능은 아닙니다.

## 검증

- JavaScript 34개 파일 문법 검사 통과.
- 자동 테스트 201개 통과, 실패·건너뜀 없음. 다른 드라이브 간 이동 검사도 포함했습니다.
- 네이티브 검사는 실제 도우미 UI 스레드를 통제된 조건에서 멈춰 연결 종료를 확인합니다. 버튼 반전·오래된 입력·취소, 감시와 드롭 확정 사이의 100회 경쟁 상황, 실제 전송 단계의 감시 제외를 확인했습니다.
- 기존 셸 COM 열거 검사는 실제 앱과 같이 응답을 모두 받은 뒤 연결을 닫도록 했습니다. 부모가 먼저 연결을 끊는 상황의 강제 종료 검사는 별도로 유지합니다.
- 배포 후보 EXE에서 셸 연동 7개, 표시·선택·이동 10개, 탐색 9개 검사 그룹이 통과했습니다. 셸 연동 화면 검사는 메뉴·드래그·클립보드 IPC를 테스트용 응답으로 대체하며, 중복 요청·늦은 응답·취소 실패와 실제 임시 파일의 복사·이동을 확인합니다.
- 포터블 런처 최초 실행·재실행·EXE와 설정 폴더 이동 후 실행이 모두 정상 종료했습니다. 3회 실행에서 폴더·분할·즐겨찾기·테마 복원을 확인했습니다.

검증한 로컬 후보 파일은 `quadpane-0.8.1-portable-x64.exe`이며 SHA-256은 `1539fd8eebe9a9fed202a5c98ea50522f0481e91e194f0df90c09aada4a4a66f`입니다. GitHub에서 별도로 빌드하는 공식 EXE의 해시는 릴리스에 첨부되는 `SHA256SUMS.txt`를 기준으로 합니다.

자동 검사에서는 사용자 마우스 입력을 보내거나 사용자 클립보드를 바꾸지 않습니다. 최초 장애의 실제 복구는 사용자 확인을 받았으며, 수정본의 물리적 탐색기·브라우저 드롭과 모든 셸 확장 조합을 자동 검사로 보증하지는 않습니다.
