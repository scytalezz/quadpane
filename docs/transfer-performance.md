# 외부 파일 작업 안정화와 시작 성능 개선

2026-10-29 갱신. [v0.9.2](releases/v0.9.2.md)에 포함된 외부 복사·붙여넣기·드래그 안정화와 성능 개선 기록입니다. 아래 성능 수치는 v0.9.1 기반 출시 전 프리뷰에서 측정했습니다.

## 수정한 원인

- Windows 탐색기에서 돌아올 때 자동 새로고침 중인 패널이 복사·붙여넣기와 드래그를 거절했습니다. 현재 폴더를 다시 읽는 동안에는 기존 선택과 목적지를 계속 사용할 수 있게 했습니다. 다른 폴더로 탐색 중일 때는 계속 차단합니다.
- 빠른 복사→붙여넣기, 연속 복사, 늦게 도착한 포커스 복귀 클립보드 응답이 서로 덮어쓸 수 있었습니다. 쓰기 순서를 보장하고, 붙여넣기는 목적지를 먼저 확정해 한 번만 실행하며, 오래된 읽기 결과는 무시합니다.
- 물리적 버튼 해제가 OLE의 해제 콜백보다 먼저 관찰되면 정상 외부 드래그도 즉시 취소됐습니다. 최대 250ms의 전달 유예를 두되, 실제 드롭은 OLE의 해제 콜백만 승인합니다. 끊긴 드래그의 종료 감시와 이미 시작한 외부 작업 보호는 유지합니다. [QueryContinueDrag 계약](https://learn.microsoft.com/en-us/windows/win32/api/oleidl/nf-oleidl-idropsource-querycontinuedrag)
- 클립보드가 잠깐 잠기면 즉시 실패했습니다. 읽기 획득만 제한적으로 재시도하고, 예외가 생겨도 COM 참조를 해제합니다. 파일 이동이나 클립보드 쓰기를 자동 재실행하지 않습니다. [OleGetClipboard 오류](https://learn.microsoft.com/en-us/windows/win32/api/ole2/nf-ole2-olegetclipboard)
- 비정상 종료한 이동 도우미의 응답을 정상적인 다른 볼륨 오류로 해석하면 이동이 재시도될 수 있었습니다. 정상 종료한 응답만 후속 처리를 결정하며, 결과가 불확실한 작업은 재실행하지 않습니다.

실제 로컬 파일 경로가 없는 브라우저의 가상 파일 드롭은 안내를 표시합니다. 웹페이지의 이미지·링크를 내려받는 기능은 포함하지 않습니다.

## 성능 변경

- 현재 보이는 패널만 조회·렌더링합니다. 보조 작업 공간과 숨긴 패널은 열 때 읽으며, 이동으로 경로가 바뀌거나 새로고침이 필요하면 해당 상태를 보관합니다. 이동으로 경로가 바뀌면 이전 목록·선택을 무효화해 옛 경로로 드롭되지 않게 합니다.
- 드라이브 열거는 기존 디렉터리 도우미를 재사용합니다. 별도 PowerShell 실행과 A~Z 드라이브 준비 상태 탐색을 제거했습니다. [GetLogicalDrives](https://learn.microsoft.com/en-us/dotnet/api/system.environment.getlogicaldrives?view=netframework-4.8.1)
- 파일별 이름 변경·이동과 복사 완료 시 최종 배치는 작은 `Quadpane.Move.exe`가 수행합니다. 덮어쓰기 금지, 긴 경로, NTFS 추가 스트림 보존은 유지합니다. 다른 볼륨의 폴더 트리 이동은 기존 구현을 사용합니다.
- 포터블 패키지에 electron-builder의 `portable.useZip` 옵션을 사용합니다. 해당 버전은 NSIS의 빠른 압축 해제를 사용하므로 시작이 빨라지는 대신 EXE가 커집니다. 임시 런타임은 종료 시 계속 정리합니다.

v0.9.1 기반 출시 전 프리뷰에서 로컬 작은 파일 12개를 순차 처리한 측정은 파일별 이동 준비/실행 비용 평균 약 252ms → 59ms, 복사 전체 서비스 비용 257ms → 61ms였습니다. 디스크 전송 자체의 속도나 대용량 파일·SMB 성능을 뜻하지 않습니다.

포터블 시작은 `scripts/verification/measure-startup.cjs`로 측정합니다. 각 실행에 별도 프로필과 같은 100개 파일 폴더를 준비하고, 런처 시작부터 4개 표시 패널의 목록 완료까지 측정합니다. 테스트 모드이므로 작업표시줄 복구·업데이트 통신은 제외하며, OS 파일 캐시를 비운 측정은 아닙니다. 기존 EXE와 시험 EXE를 같은 명령에 전달하면 각각 3회와 중앙값을 기록합니다.

기존 v0.9.1과 v0.9.1 기반 출시 전 프리뷰를 비교한 중앙값은 **8.33초 → 4.90초(약 41% 단축)**였습니다. 로컬 파일 100개·표시 패널 4개·각 3회, OS 파일 캐시가 남아 있는 웜 캐시 조건입니다. EXE는 **109,282,977 → 157,744,028바이트(약 109 → 158MB)**로 커졌습니다. v0.9.2 최종 배포본의 측정값이나 모든 PC에서의 속도 향상을 보장하는 수치가 아닙니다.

기록은 `.checks/startup-timing/run-1793254063932/results.json`에 있으며, **측정 프리뷰 EXE**의 SHA-256은 `f53d155161ea7cd7647b9ca47ff896951e4f9bda615ea73282fcb6618d1b2154`입니다. 이 해시는 v0.9.2 최종 릴리스의 해시가 아닙니다.

## 검증 범위

- 자동 테스트: 클립보드 응답 역전·빠른 붙여넣기·드래그 콜백 순서·취소/종료·안전한 이동 실패 분류.
- 실제 파일 테스트: 같은/다른 볼륨 이동, 이름 충돌, 잠긴 파일, 부분 실패, 긴 한글 경로, NTFS 스트림, 재실행 후 설정 복원.
- 렌더러 통합: 실제 파일을 담은 `File` 드롭과 복사/이동, 지연 응답 중 중복 요청 억제, 숨긴 패널의 경로 변경 및 표시 시 조회.
- 실제 사용자 클립보드와 전역 마우스 입력은 변경하지 않았습니다. 물리적인 마우스로 Explorer·브라우저까지 드롭하는 전체 경로 및 회사 PC의 셸 확장은 자동 검증 범위에 포함되지 않습니다.

앞선 출시 전 단위 테스트는 전체 실행 361개 통과에 별도 볼륨 이동 검사 4개를 더해 **중복을 제외한 365개 통과·환경 조건 2개 건너뜀**이었습니다. 이후 v0.9.2 전체 재실행에서도 365개 통과·2개 건너뜀을 확인했습니다(`.checks/release-092-tests.log`). 남은 2개는 파일 심볼릭 링크 권한과 선택적 SMB 공유 조건입니다. JavaScript 52개 파일 문법 검사, 네이티브 도우미 3개와 포터블 빌드도 통과했습니다.

앞선 렌더러 경합 시나리오 24개, 드래그 복구 9개 그룹, 포터블 최초 실행·재실행·이동 후 실행 총 3회도 통과했습니다. 이는 최종 v0.9.2 EXE 실행 검증과 구분합니다. 별도 검토에서 발견한 두 경계 상황은 보완 후 재검토를 통과했습니다.

측정 프리뷰는 `dist-portable/preview-performance/`에 별도로 보관합니다. v0.9.2 배포 파일은 `quadpane-0.9.2-portable-x64.exe`이며, 다운로드한 파일의 해시는 릴리스의 `SHA256SUMS.txt`로 확인합니다.
